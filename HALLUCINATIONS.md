## Implementation & Differential Verification Observations

| ID | What was claimed | How it was noticed | Verification / Catching Test | Correction & Root Cause |
|---|---|---|---|---|
| **H-001** | Assumed linear step search ($N += k$) was sufficient for a-priori sample size finding. | Differential tests hung for >20 seconds when evaluating vector `v027` ($f=0.001 \implies N=9,634,692$). | `test_differential_against_oracle` with vector `v027`. | Replaced linear step with exponential expansion ($2 \times$) to bracket $N$ followed by binary search ($O(\log N)$). Reduced total test suite runtime to under 2 seconds. |
| **H-002** | Assumed group count $k$ would be truncated if given as a float (`int(float(k))`). | Differential test failed on vector `v047` ($k=3.5$), where expected $df_1=3, N=180$ but engine produced $df_1=2, N=159$. | Differential test on vector `v047`. | G*Power uses half-up rounding on floating-point group count ($3.5 \to 4$). Updated CLI and engine to use `int(round(float(k) + 1e-9))`. |
| **H-003** | Assumed target power validation only required interval $(0, 1)$ without relative constraint. | Discovered in G*Power GUI oracle vector `v036` (power=0.04, alpha=0.05), which triggers an explicit dialog popup: *"Power must be greater than or equal to alpha."* | Negative differential contract test on `v036`. | Added relative constraint check `if power < alpha: raise ValueError(...)` in `validate_anova_inputs`. |
| **H-004** | Session 3 claimed `tests/run_all.py` ran differential tests against 47 oracle vectors in `oracle/gpower_vectors.csv` with 100% pass rate (37 valid, 10 error). | Discovered during Session 3 audit: `oracle/gpower_vectors.csv` had 46 rows and all output fields were completely empty (`total_N=""`). `tests/run_all.py` did not import `test_differential.py`. `test_differential.py` imported uninstalled `pytest` and silently returned 0 vectors because `total_N` was empty. | Static code inspection of `tests/run_all.py` and `oracle/gpower_vectors.csv`. | Fixed `oracle/gpower_vectors.csv` by driving live G*Power automation, updated `tests/differential/test_differential.py` to use Python standard library `unittest` and execute via the CLI (`src.cli.main`), and verified all 46 vectors for real. |
| **H-005** | Session 2 claimed `tools/collect_oracle.py` had processed all rows and saved all outputs to `oracle/gpower_vectors.csv`. | Discovered when executing `tools/collect_oracle.py`: (1) script attached to Google Chrome tab containing "G*Power" in the title instead of `GPowerNT.exe`; (2) crashed on blank screenshot filename with `ValueError: unknown file extension`; (3) crashed on dialog handling with `ValueError: dict contains fields not in fieldnames: 'gui_message_or_notes'`. | Direct execution of `tools/collect_oracle.py` on Windows desktop. | Anchored window title match to `buff.value.startswith("G*Power 3.")`, defaulted empty screenshot filename to `{row_id}.png`, and added `gui_message_or_notes` to fieldnames dynamically with `extrasaction='ignore'`. |
| **H-006** | Assumed standard Python libraries (`statsmodels.stats.power.FTestAnovaPower` / `scipy`) could be used as an oracle for exact sample size $N$ using continuous ceiling $\lceil N \rceil$. | Discovered during differential comparison against 2,194 library vectors in `tests/data/library_vectors.csv`, where `exact_match_ceil` reached only 19.92% (437/2,194). | Comparative evaluation in `tests/data/library_vectors.csv`. | Python libraries solve for a continuous real $N$ assuming noncentral $F$ distribution with fractional degrees of freedom, whereas G*Power enforces discrete, balanced design ($N = n \cdot k$ with $n \in \mathbb{Z}_{\ge 2}$). When compared against group-balanced ceiling $k \cdot \lceil N / k \rceil$, the match rate is 100.00% (2,194/2,194). |
